# Table sorting and frozen session order

Both queue tables cycle their heading sort through ascending, descending and original chronological order. The active heading has a direction arrow. A real checkbox in the title heading moves completed jobs to the end in their original order while a sort is active. It leaves partial jobs in the sorted group and never hides rows. Canceling the sort restores the entire original order even when the checkbox is checked.

The main **Start/Wznów widoczne (N)** now captures only eligible, enabled recordings visible after the table's search and filters. **Start zaznaczonych (N)** captures their selected subset. Both save the table order at Start. Later changes to the view and newly imported recordings take effect at the next Start. The active session displays its saved scope and remaining work, and latches the corresponding button.

`Store.start` and `launch` accept optional `order_ids` and `scope_mode` arguments. SQLite stores ordered IDs separately from normalized membership IDs. An ordered session claims pending, enabled jobs by their saved ordinal, honoring the existing stop and once-per-session retry safeguards. Defaults retain the legacy chronological CLI behavior. Migration adds two control fields without changing jobs or starting a session.

The shared table controller persists independent settings for YouTube and local recordings in `tabele-ui.json`. Text keys respect Polish letters without changing process locale; numeric columns use source values and unknown values stay last. Selection and scrolling survive refresh. The header checkbox supports resizing, horizontal scrolling, theme changes, Space and F1. Double clicks open results only in data rows.
