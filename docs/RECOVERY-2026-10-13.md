# Continuous local queue and partial vocal recovery

Local Start includes all enabled recordings. Selected Start uses only the selected IDs. Success, a file error, and a partial export advance to the next recording. Each recording is attempted at most once per session, including when Retry is clicked during an active session. A user stop request finishes the current recording; unavailable shared models, memory exhaustion, or insufficient disk space stop the session.

The selected audio track is decoded with its timestamps aligned to the video origin. Verified source EOF before the end of the video is filled with silence. Shortened UVR output is treated separately: existing blocks and an interior vocal prefix are retained. One additional pass uses 60-second cores and the configured UVR overlap. A later Start attempts the remaining part once. Neither recovery nor joining stretches audio or changes sample positions.

A partial job has its full duration, processed sample boundary, error code, and error history in SQLite. Its TXT, SRT, VTT, and JSON filenames contain `_czesciowa`, and `czesciowe.json` commits the verified set. Complete results require `gotowe.json` and all verified exports. Partial audio, PCM, and checkpoints stay available. Per-block audio hashes let Whisper and diarization retain unchanged prefix blocks when the tail grows. Historical complete exports remain valid.

Folder scanning descends through every level when Subfolders is enabled, skipping owned output directories, links, and junctions. M4A-only filters the next scan; changing either option does not itself import files. Inaccessible directories are listed in `ostatni-import-lokalny.json` beside the queue registry.
